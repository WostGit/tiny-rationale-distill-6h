# Tiny Rationale Distillation (6h GitHub Actions Study)

This repository is a **tiny reduced reproduction** of rationale-distillation behavior under strict CPU constraints. It is intentionally scoped for readability/reproducibility on standard GitHub-hosted runners (Ubuntu, CPU-only, LoRA-only), not benchmark-grade SOTA claims. The study compares answer-only supervision vs short/compressed rationale supervision vs full-rationale supervision at tiny data budgets across multiple seeds, with contamination-aware checks and machine-readable artifacts.

## Research question

At tiny data budgets, does short/compressed rationale supervision transfer more useful signal to a fixed small student than answer-only or full-rationale supervision under contamination-aware evaluation?

## Supervision formats

- `answer_only`: target includes only final answer.
- `short_rationale`: compressed explanation + explicit final answer.
- `full_rationale`: longer step-by-step explanation + explicit final answer.

## Tasks

1. **Arithmetic**
   - Train/eval split with disjoint operand ranges.
   - Train range: small operands (`1..20`), eval range: held-out larger operands (`101..130`).

2. **Symbolic rule-following**
   - Deterministic transformation task: shift each symbol by +1 in a fixed vocabulary, then reverse sequence.
   - Train/eval split with disjoint sequence-length regimes and separate RNG seeds.
   - Data generated by `scripts/generate_symbolic_data.py`, with checked-in JSONL files.

## Contamination controls

- Strict train/eval file separation per task.
- Arithmetic uses disjoint operand ranges across split.
- Symbolic uses separate generation regimes (length range + seeds) across split.
- `scripts/contamination_audit.py` emits machine-readable JSON containing:
  - exact input overlap count/examples
  - simple character 3-gram overlap (Jaccard)
  - protocol note explaining leakage minimization

## Experimental grid

- Tasks: `arithmetic`, `symbolic`
- Supervision: `answer_only`, `short_rationale`, `full_rationale`
- Budgets: `16, 32, 64, 128`
- Seeds: 5 defaults (`11..15`)
- Epochs: default `3`

Total default grid: **2 × 3 × 4 × 5 = 120 conditions**.

Fixed across conditions: student model, optimizer, LoRA config, decoding settings.  
Varied only: task, supervision format, budget, seed.

## What this study proves and does not prove

**Can show:**
- Whether short/full rationale supervision changes sample efficiency vs answer-only in this tiny controlled setup.
- How robust those differences are across seeds and tiny budgets.

**Cannot show:**
- General benchmark-level conclusions.
- Claims that transfer to larger models, larger corpora, or broader reasoning tasks.

## Predicted results based on prior literature

Prior distillation literature often finds rationale supervision can help small students, while more recent findings suggest rationale quality/length selection matters. In this tiny setting, we expect:
- `short_rationale` to often outperform `answer_only` at low budgets.
- `full_rationale` to help sometimes, but potentially be less sample-efficient than concise rationales.

These are hypotheses, not guaranteed outcomes.

## How to run locally

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
python scripts/generate_symbolic_data.py --output_dir data --train_size 256 --eval_size 128 --seed 17
python scripts/run_6h_study.py \
  --tasks "arithmetic,symbolic" \
  --supervision_formats "answer_only,short_rationale,full_rationale" \
  --budgets "16,32,64,128" \
  --seeds "11,12,13,14,15" \
  --epochs 3 \
  --output_root outputs/metrics
```

## How to run on GitHub Actions

Primary path is `.github/workflows/run-6h-study.yml`.

- Triggers: `push`, `pull_request`, `workflow_dispatch`
- Uses GitHub-hosted `ubuntu-latest` runner
- CPU-only
- Matrix over `(task, supervision)` with per-shard sweep over budgets/seeds
- Uploads `outputs/metrics` as artifacts

## How to inspect outputs

Everything lands under `outputs/metrics/`:

- `*/train_metrics.json`: per-condition training metrics
- `*/eval_metrics.json`: per-condition evaluation metrics
- `*/prediction_samples.jsonl`: compact prediction samples
- `condition_results.json` / `.csv`: condition-level table
- `summary_over_seeds.json` / `.csv`: mean/std across seeds
- `comparison_table.md`: markdown comparison table
- `scaling_curve_<task>.png`: publication-style scaling curves
- `audit_<task>_<supervision>.json`: contamination audit outputs

## Notes on implementation choices

- Student model default: `distilgpt2` (small causal LM)
- Adaptation: **PEFT LoRA only**
- Full fine-tuning: not used
- Minimal checkpointing: adapter + compact metrics only
- Deterministic seeding enabled
- Resumable behavior: conditions with existing metrics are skipped unless `--overwrite`
