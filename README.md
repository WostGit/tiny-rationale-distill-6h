# Tiny Rationale Distillation (6h CPU GitHub Actions Study)

This repository is a **tiny reduced reproduction** (not a benchmark-grade paper reproduction) of rationale-distillation style experiments. It compares answer-only supervision, short/compressed rationale supervision, and full-rationale supervision for a fixed small student with LoRA-only fine-tuning on CPU.

## Research question
At tiny data budgets, does short/compressed rationale supervision transfer more useful signal to a fixed small student than answer-only or full-rationale supervision under contamination-aware evaluation?

## Supervision formats
- `answer_only`: target only contains the final answer string.
- `short_rationale`: compact rationale with one concise transformation/explanation and explicit final answer.
- `full_rationale`: longer step-by-step rationale with explicit final answer.

## Tasks
1. **Arithmetic**
   - Expressions with `+`, `-`, `*`.
   - Train/eval use disjoint operand ranges to reduce leakage.
2. **Symbolic rule-following**
   - Deterministic transform: reverse sequence then shift symbols by +1 cyclically.
   - Generated by `scripts/generate_symbolic_data.py` and final JSONL is checked in.

## Contamination controls
- Separate train/eval files per task.
- Arithmetic uses range split (train small operands, eval larger operands).
- Symbolic uses split data regimes and independent generation streams.
- `scripts/contamination_audit.py` emits:
  - exact input overlap count
  - simple character 5-gram overlap statistic
  - protocol note explaining leakage minimization
- Audit output written to `outputs/metrics/contamination_audit.json`.

## Experimental grid
- Tasks: `arithmetic`, `symbolic`
- Formats: `answer_only`, `short_rationale`, `full_rationale`
- Budgets: `16`, `32`, `64`, `128`
- Seeds: `0..4` (5 seeds)
- Epochs: default `3`
- Total conditions: `2 x 3 x 4 x 5 = 120`

Fixed across conditions:
- Student model (`roneneldan/TinyStories-33M` by default)
- Optimizer (AdamW)
- LoRA config
- Decoding settings

Varied:
- task, supervision format, budget, seed

## What this study proves and does not prove
**Can show:** whether, in this tiny controlled setup, short rationales look more sample-efficient than answer-only or long rationales.

**Cannot show:** benchmark-level general conclusions, SOTA claims, or strong external validity across large models/tasks.

## Predicted results based on prior literature
Prior literature suggests chain-of-thought/rationale distillation can help small students and that rationale selection/quality may matter. This tiny study tests the directional hypothesis that **short/compressed rationales may outperform both answer-only and verbose rationales at low budgets**, without overclaiming broad generality.

## How to run locally
```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python scripts/contamination_audit.py
python scripts/run_6h_study.py --resume
```

Single condition example:
```bash
python scripts/train_tiny_distill.py --task arithmetic --supervision-format short_rationale --budget 32 --seed 0 --epochs 3
python scripts/eval_tiny_distill.py --task arithmetic --supervision-format short_rationale --budget 32 --seed 0
```

## How to run on GitHub Actions
Main path is `.github/workflows/run-6h-study.yml`.
- Triggered on `push`, `pull_request`, and `workflow_dispatch`.
- Uses 6 matrix shards over the 120-condition grid.
- Each shard trains/evals its subset and uploads artifacts.
- Aggregate job combines outputs and writes summaries/tables/audit.

## How to inspect outputs
Everything lands under `outputs/metrics/`:
- per-condition:
  - `train_metrics.json`
  - `eval_metrics.json`
  - `prediction_samples.json`
  - LoRA adapter folder
- global:
  - `all_conditions.json`
  - `summary_by_budget.csv`
  - `summary_by_budget.json`
  - `comparison_table.md`
  - `contamination_audit.json`
  - `scaling_arithmetic.png`, `scaling_symbolic.png`

## Notes on reproducibility
- Deterministic seeding in training.
- Resumable mode (`--resume`) skips completed condition files.
- Compact machine-readable JSON outputs for each condition.
